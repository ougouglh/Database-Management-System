# 多阶段系统升级设计方案

## 一、设计原则

基于现有系统进行**渐进式升级**，最大程度保留现有代码和逻辑，避免大规模重构。

### 1.1 保留部分
- 现有 FastAPI 后端架构
- 现有数据库连接和配置方式
- 现有导入导出核心逻辑
- 现有数据校验模块

### 1.2 新增部分
- 用户认证模块
- 操作日志模块
- 五阶段配置化管理
- Vue 3 前端项目

### 2.3 数据库设计

#### 2.3.1 新增系统表

```sql
-- 用户表
CREATE TABLE sys_user (
    id INT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) UNIQUE NOT NULL COMMENT '用户名',
    password_hash VARCHAR(255) NOT NULL COMMENT '密码哈希',
    real_name VARCHAR(100) COMMENT '真实姓名',
    email VARCHAR(100) COMMENT '邮箱',
    role_id INT COMMENT '角色ID',
    is_active BOOLEAN DEFAULT TRUE COMMENT '是否启用',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';

-- 角色表
CREATE TABLE sys_role (
    id INT PRIMARY KEY AUTO_INCREMENT,
    role_name VARCHAR(50) NOT NULL COMMENT '角色名称',
    role_code VARCHAR(50) UNIQUE NOT NULL COMMENT '角色编码',
    description VARCHAR(200) COMMENT '描述',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='角色表';

-- 初始化角色数据
INSERT INTO sys_role (role_name, role_code, description) VALUES
('管理员', 'admin', '拥有所有权限'),
('运营人员', 'operator', '可操作所有阶段'),
('品类专员', 'category_specialist', '可操作第一、二阶段'),
('校验员', 'validator', '可操作第三阶段'),
('查看员', 'viewer', '只读权限');

-- 角色权限表
CREATE TABLE sys_role_permission (
    id INT PRIMARY KEY AUTO_INCREMENT,
    role_id INT NOT NULL,
    stage_id INT NOT NULL COMMENT '阶段ID：1-5，0表示系统管理',
    can_import BOOLEAN DEFAULT FALSE COMMENT '可导入',
    can_export BOOLEAN DEFAULT FALSE COMMENT '可导出',
    can_view BOOLEAN DEFAULT FALSE COMMENT '可查看',
    can_edit BOOLEAN DEFAULT FALSE COMMENT '可编辑',
    FOREIGN KEY (role_id) REFERENCES sys_role(id),
    UNIQUE KEY uk_role_stage (role_id, stage_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='角色权限表';

-- 操作日志表
CREATE TABLE sys_operation_log (
    id INT PRIMARY KEY AUTO_INCREMENT,
    user_id INT NOT NULL COMMENT '用户ID',
    username VARCHAR(50) COMMENT '用户名',
    operation_type VARCHAR(20) NOT NULL COMMENT '操作类型：login/import/export/view/edit/delete',
    stage_id INT COMMENT '阶段ID',
    table_name VARCHAR(50) COMMENT '操作的表名',
    affected_rows INT DEFAULT 0 COMMENT '影响行数',
    status VARCHAR(20) DEFAULT 'success' COMMENT '状态：success/failed',
    error_message TEXT COMMENT '错误信息',
    ip_address VARCHAR(50) COMMENT 'IP地址',
    user_agent TEXT COMMENT '用户代理',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '操作时间',
    INDEX idx_user_created (user_id, created_at),
    INDEX idx_stage_created (stage_id, created_at),
    INDEX idx_operation_type (operation_type)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='操作日志表';
```

### 2.4 API 设计

#### 2.4.1 认证相关（新增）

| 路径 | 方法 | 说明 | 认证 |
|------|------|------|------|
| /api/auth/login | POST | 用户登录 | 否 |
| /api/auth/logout | POST | 用户登出 | 是 |
| /api/auth/info | GET | 获取当前用户信息 | 是 |
| /api/auth/users | GET | 获取用户列表（管理员） | 是 |
| /api/auth/users | POST | 创建用户（管理员） | 是 |

| 路径 | 方法 | 说明 | 认证 |
|------|------|------|------|

| /api/stage/{stage_id}/preview | POST | 预览变更 | 是 |
| /api/stage/{stage_id}/import | POST | 执行导入 | 是 |
| /api/stage/{stage_id}/export | POST | 导出数据 | 是 |
| /api/stage/{stage_id}/data | GET | 获取数据列表 | 是 |
| /api/stage/{stage_id}/columns | GET | 获取表字段 | 是 |
| /api/stage/{stage_id}/stats | GET | 获取统计信息 | 是 |

### 3.5 状态管理

#### 3.5.1 user.js（用户状态）

```javascript
import { defineStore } from 'pinia'

export const useUserStore = defineStore('user', {
  state: () => ({
    token: localStorage.getItem('token') || '',
    userInfo: null,
    permissions: []
  }),

  getters: {
    isLoggedIn: (state) => !!state.token,
    hasPermission: (state) => (stageId, action) => {
      const perm = state.permissions.find(p => p.stage_id === stageId)
      return perm ? perm[`can_${action}`] : false
    }
  },

  actions: {
    async login(username, password) {
      const res = await api.auth.login({ username, password })
      this.token = res.data.access_token
      this.userInfo = res.data.user
      this.permissions = res.data.user.permissions
      localStorage.setItem('token', this.token)
    },

    logout() {
      this.token = ''
      this.userInfo = null
      this.permissions = []
      localStorage.removeItem('token')
    }
  }
})
```

import { defineStore } from 'pinia'

export const useStageStore = defineStore('stage', {

      this.stages = res.data
