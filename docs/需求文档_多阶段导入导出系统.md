# 多阶段商品数据管理导入导出系统需求文档

## 一、项目概述

### 1.1 项目背景

现有系统为单表商品数据管理，需升级为多阶段数据流转管理系统，支持商品从品类定义到最终的全流程管理。

### 1.2 项目目标

实现商品数据在五个阶段间的有序流转，每个阶段独立管理、可追溯、可审计。

***

## 二、系统架构

### 2.1 技术栈

- **后端**: FastAPI + Python
- **前端**: Vue 3 + Element Plus + Vite
- **状态管理**: Pinia
- **路由**: Vue Router 4
- **HTTP**: Axios
- **数据库**: MySQL

### 2.2 系统模块

```
┌─────────────────────────────────────────────────────────────┐
│                    用户认证与权限管理                          │
├─────────────────────────────────────────────────────────────┤
│  操作日志记录  │  用户管理  │  角色权限  │  登录认证         │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                      五阶段数据流转                            │
├──────────┬──────────┬──────────┬──────────┬─────────────────┤
│  第一阶段  │  第二阶段  │  第三阶段  │  第四阶段  │    第五阶段      │

```

### 3.3 导入功能设计

#### 3.3.1 导入流程

```
1. 选择阶段 → 2. 上传文件 → 3. 数据校验 → 4. 变更预览 → 5. 确认导入
```

#### 3.3.2 导入步骤说明

**步骤1：选择阶段**
用户在功能导航页面选择对应阶段和"导入"功能

**步骤2：上传文件**

- 支持 .xlsx, .xls, .csv 格式
- 文件大小限制：50MB

**步骤3：数据校验**

- 必填字段校验
- 字段格式校验
- 数据类型校验
- 重复数据校验
- 返回校验结果（错误数/警告数）

**步骤4：变更预览**

- 显示本次导入将变更的记录数
- 列出变更详情（新增/修改/删除）
- 显示变更前后对比（Diff视图）
- 支持分页查看变更记录

**步骤5：确认导入**

- 用户确认后执行导入
- 导入模式：覆盖式更新（根据item\_barcode匹配，存在则更新，不存在则新增）
- 记录操作日志
- 显示导入结果摘要

#### 3.3.3 导入日志格式

```
导入时间: 2024-01-15 14:30:25
操作人: 张三
阶段: 第一阶段-品类定义
文件: category_data_20240115.xlsx
导入结果:
  - 总记录数: 1,500
  - 新增: 200
  - 更新: 1,200
  - 失败: 100
  - 耗时: 3.2秒
```

### 3.4 导出功能设计

#### 3.4.1 导出流程

```
1. 选择阶段 → 2. 选择字段 → 3. 设置筛选条件 → 4. 预览SQL → 5. 执行导出
```

#### 3.4.2 筛选条件

**通用筛选条件**:

- 商品条码（精确/模糊）
- 商品名称（模糊）
- 创建时间范围
- 更新时间范围

**阶段特定筛选**:

- 第一阶段：品类名称、品类编码
- 第二阶段：变更原因、处理人
- 第三阶段：平台名称、校验状态
- 第四阶段：企业名称、品牌名称、Mapping类型
- 第五阶段：发布状态、最终品类

#### 3.4.3 导出格式

- Excel (.xlsx)
- CSV (.csv)
- 导出文件命名：`{阶段名}_export_{时间戳}.xlsx`

#### 3.4.4 导出限制

- 单次导出最多100,000条
- 超大数据量需分段导出
- 记录导出操作日志

## 五、数据库设计

### 5.1 用户表 (sys\_user)

```sql
CREATE TABLE sys_user (
    id INT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    real_name VARCHAR(100),
    email VARCHAR(100),
    role_id INT,
    is_active BOOLEAN DEFAULT TRUE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

### 5.2 角色表 (sys\_role)

```sql
CREATE TABLE sys_role (
    id INT PRIMARY KEY AUTO_INCREMENT,
    role_name VARCHAR(50) NOT NULL,
    role_code VARCHAR(50) UNIQUE NOT NULL,
    description VARCHAR(200),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 5.3 角色权限表 (sys\_role\_permission)

```sql
CREATE TABLE sys_role_permission (
    id INT PRIMARY KEY AUTO_INCREMENT,
    role_id INT NOT NULL,
    stage_id INT NOT NULL,
    can_import BOOLEAN DEFAULT FALSE,
    can_export BOOLEAN DEFAULT FALSE,
    can_view BOOLEAN DEFAULT FALSE,
    can_edit BOOLEAN DEFAULT FALSE,
    FOREIGN KEY (role_id) REFERENCES sys_role(id)
);
```

### 5.4 操作日志表 (sys\_operation\_log)

```sql
CREATE TABLE sys_operation_log (
    id INT PRIMARY KEY AUTO_INCREMENT,
    user_id INT NOT NULL,
    username VARCHAR(50),
    operation_type VARCHAR(20) NOT NULL,
    stage_id INT,
    table_name VARCHAR(50),
    affected_rows INT DEFAULT 0,
    status VARCHAR(20) DEFAULT 'success',
    error_message TEXT,
    ip_address VARCHAR(50),
    user_agent TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_user_created (user_id, created_at),
    INDEX idx_stage_created (stage_id, created_at)
);
```
